## Working Principles

- Keep changes focused and understandable.
- Prefer the simplest design that solves the current problem.
- Keep responsibilities clear. Each module, file, or section should have one
  main reason to change.
- Avoid duplicating logic, rules, or documentation. If the same idea appears in
  multiple places, keep one place authoritative and link to it.
- Keep project boundaries clean. Do not mix unrelated concerns just because it
  is convenient in the moment.
- When replacing behavior, remove obsolete code, paths, documentation, and
  examples that no longer apply.
- Update relevant documentation when behavior, scope, or expectations
  change.
- Verify important behavior with examples, review, or other project-appropriate
  evidence.
- Use real examples, sample data, or screenshots when they make review easier.
- Do not include secrets, private data, credentials, or local-only files in
  shared project history.
